# 3주차 산출물 — 데이터 품질 리포트

## 1. 대상
- 원본: orders.csv (1,015행) — 3-1에서 생성, 시드 고정
- 정제 결과: orders_clean.parquet (1,000행)
- 파이프라인: clean_orders.py (DuckDB 추출 + Pandas 정제)

## 2. 품질 지표 전후 비교
| 지표 | before | after |
|---|---|---|
| 행 수 | 1,015 | 1,000 |
| order_id 중복 | 15 | 0 |
| price 결측 | 30 (2.96%) | 0 |
| category 고유값 | 5 | 4 |

## 3. 처리 내용과 근거
| 문제 | 처리 | 근거 |
|---|---|---|
| category 앞뒤 공백 20건 | str.strip() | ' 식품 '이 '식품'과 다른 값으로 집계돼 카테고리가 5가지로 세어짐 |
| order_date 타입 | to_datetime() | DuckDB 로 읽으면 이미 날짜지만, pd.read_csv 로 읽으면 문자열이라 같은 결과를 보장하려고 남김 |
| order_id 중복 15건 | drop_duplicates(keep='first') | 같은 주문이 두 번 세어져 매출이 부풀려짐 |
| price 결측 30건 | 중복 제거 뒤 중앙값으로 보정 | 결측률 2.96%로 낮음 · 이상치에 흔들리지 않는 중앙값 · 순서를 바꾸면 중앙값이 달라짐(100,500 vs 101,000) |

## 4. 고치지 않은 것
| 항목 | 판단 | 근거 |
|---|---|---|
| 보정한 price 30건의 표시 | 구분 열 없이 둠 | 이번 리포트 범위는 지표 개선까지로 한정 — 6절 과제로 넘김 |
| 고액 주문 (최대 199,000원) | 정상값으로 보고 유지 | 생성 범위(1,000~199,000원) 안이고, IQR 기준 이상치 0건 |
| 중복 15건 중 어느 행을 남길지 | keep='first' 그대로 | 중복 쌍의 모든 열 값이 완전히 같아 어느 쪽을 남겨도 결과 동일 |
| order_date 범위 | 수정 없음 | 2026-06-01 ~ 2026-07-30으로 생성 기간(60일) 안 |
| customer_id 참조 | 수정 없음 | 1~200으로 고객 마스터(customers.csv) 범위 안 |

## 5. 검증
- 재실행 검증: 같은 원본으로 두 번 돌려 결과가 동일함을 확인 (equals() True)
- 교차 검증: DuckDB로 다시 측정해 Pandas 결과와 일치 확인
- 유효성 검사: 음수 가격·수량, 미지 카테고리 0건
- 검사기 자체 검증: 일부러 나쁜 값을 넣어 검사기가 잡는 것을 확인

## 6. 남은 과제
- **분석 입력 교체**: 3-1~3-4 분석에 쓴 `orders_step1.parquet`는 중복 제거 전(1,015행) 데이터라 매출이 부풀어 있음 → 분석 입력을 `orders_clean.parquet`로 바꿔야 함
- **보정값 표시**: 중앙값으로 채운 30건을 원래 값과 구분할 수 없음 → `price_imputed` 플래그 열 추가
- **검사 기준일 고정**: `validate_test.py`의 미래 날짜 검사가 실행일(`Timestamp.today()`) 기준이라 실행하는 날에 따라 결과가 바뀔 수 있음 → 기준일을 인자로 받거나 데이터 수집일로 고정
- **값 범위 점검 반영**: 미니 과제([mini/](mini/))에서 만든 가격·수량 범위 점검을 `clean_orders.py`의 `validate()`에도 넣기 (현재는 수량 상한 검사가 없음)
