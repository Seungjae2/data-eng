## 3-3 실측 기록 (본인 환경)

| 항목 | CSV | Parquet(zstd) | 배율 |
|---|---|---|---|
| 파일 크기 | 40.6 MB | 9.8 MB | 4.1배 작아짐 |
| 집계 질의 | 0.063초 | 0.001초 | 47.3배 빠름 |
| 한 열만 읽기 | 0.060초 | 0.0006초 | — |
| 다섯 열 읽기 | 0.067초 | 0.0048초 | — |

압축 방식 비교: zstd 9.8 MB / snappy 15.9 MB / gzip 10.6 MB

거꾸로 나온 측정: count(*) 로 잰 「전부 읽기」가 더 빨랐던 이유 — DuckDB는 count(*) 수행 시 실제 열 데이터를 읽지 않고, Parquet 파일 메타데이터에 기록된 총 행 수만 바로 가져와 반환하기 때문 (열 스캔 단계 생략)

결론: 열 지향 압축(zstd)으로 용량을 약 4배 절감하고, 필요한 열만 읽어 질의 속도를 수십 배(약 47배) 향상시킬 수 있으므로 대용량 데이터 처리의 중간 산출물로 Parquet를 사용한다.
